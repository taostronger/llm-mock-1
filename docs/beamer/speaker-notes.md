# 面试项目介绍：讲述提示

配套 [Beamer PDF](project-introduction.pdf)，题名《大模型基础设施与 Agent 工程》。共 44 页：主讲 1–26，技术备份 27–44。面试时先说明项目是什么，再讲自己负责什么、怎样实现、如何验证；按面试官关注点进入备份。

## 开场（约 40 秒）

> 我参与过几类大模型基础设施项目。推理方向是 OmniInfer 和后续独立的 Omni-EPLB，我主要做专家负载均衡、运行时与框架接入，也参与一些模型配置和兼容修复。平台方向包括基于 DataHub 的数据工程平台，以及基于 LiteLLM 的多后端推理网关。最近还有路由 simulator 和编码 Agent 平台，重点是实验工具、双 worker 协作与 Harness² 执行接入。接下来我先介绍各个项目的整体背景，再定位我的模块和具体技术点。

## 各项目的一分钟入口

**OmniInfer / Omni-EPLB**

> OmniInfer 是一个面向大模型服务的总体推理加速框架，除了专家均衡，还包括注意力和预填充/解码调度方面的团队能力。我主要负责其中的专家均衡相关工作：从工作量模型和副本布局，到 C++/Python 运行时、权重迁移、映射更新及工具测试，也参与了模型配置和局部兼容修复。相关能力后来独立演进为 Omni-EPLB SDK，我继续参与接入与通信能力延续。下面我会把总体框架、独立 SDK 和个人实现分别讲清楚。

**数据工程平台**

> 这个项目面向数据工程团队，目标是把资产、产线版本和生产任务放在可追溯的流程里。DataHub 提供元数据底座，但整个生产平台由团队建设。我主要负责注册 SDK 和扩展 API、企业身份与角色权限、GMS/Play/React 适配，以及 Data Agent 的元数据工具与实体链接。这里能体现 Python、Java 和前端之间的接口与一致性工程。

**Omni-ELB / LiteLLM 与 simulator**

> 网关位于应用和多套模型后端之间。团队基于 LiteLLM 提供统一调用入口，我与同事共同设计会话亲和和负载路由，并独立实现状态刷新、漏刷诊断和重复计量修复。为了用固定输入检查策略，我还做了 simulator：直接挂载真实插件，维护请求事件和在途状态，用可替换后端产生服务耗时。它是实验工具，生产链路不会经过它。

**编码 Agent 平台**

> 这个平台让个人或小团队管理多个编码 Agent 的任务、执行和结果。我主要做 Delm 双 worker 协作适配，以及 Harness² 执行接入。前者把自然语言协作变成看板任务和可追踪事件；后者让提示、工具和协作配置能够进入同一实际执行路径，收回轨迹和产物。个人工程重点包括输入准备、运行隔离、已有文件修改检测、逐 worker 停滞和结果回收。
