# 项目介绍讲述提示

配套 [Beamer PDF](project-introduction.pdf)。共 42 页，1–38 为正文，39–42 为技术附录。讲述者：陶壮（Zhuang Tao）。这份稿用于学术和工程交流，不沿用历史出站答辩的组织身份、日期或致谢内容。

## 页序与要点

| 页 | 讲述重点 |
|---|---|
| 1 | 用“大模型系统与智能体工程”概括方向。五项工作有共同的方法问题，但来自不同项目。 |
| 2 | 按资源分配、状态治理、服务验证、Agent 执行逐一定位；不画未经证实的统一生产架构。 |
| 3 | MoE 的稀疏激活不意味着设备负载自动平衡，单轮可能被最忙设备限制。柱状图仅为解释机制。 |
| 4 | 先求副本子问题。12/8/4/4 的例子解释两个副本预算怎样使最大单副本压力从 12 降到 6；最优性有固定负载、等成本和均匀分担前提。 |
| 5 | 将副本放到设备后，还要检查容量、同卡唯一性和组合负载。示例两卡各 14；不能从单副本最优直接推出设备最优。 |
| 6 | 监测到的物理槽计数须还原为逻辑专家工作量。项目运行时用不均衡触发和候选代理改善门槛，不把模拟的时间成本判据说成已部署。 |
| 7 | 算法给出目标后，迁移还要拆批、同步并在安全点切换映射。本人工作聚焦优化器、批量传输、工具与测试，不将全框架归为个人。 |
| 8 | 从采集窗口、prefill/decode 口径和 rank 记录讲到激活工作量 CSV、Pattern 与视图。离线转换需核对采集位置与专家编号，不默认读取当前运行时映射。当前独立检查覆盖和槽位一致性，不是完整形式验证。 |
| 9 | 说明接口如何接入框架：门控逻辑选择保持，plan使用传入的当前层映射转换物理位置；record_activation收集状态，place_experts在安全点生效。模型层索引和特殊专家差异在适配层处理。 |
| 10 | 展示公开合成结果：热点变化时动态调整有价值，稳态时可保持。单层时间来自假定速率与同步复制开销，不是设备实测。 |
| 11 | 元数据平台面向注册、授权、发现和消费。API 入口调用 SDK，进程内也可直接调用 SDK；图为功能概述，不是部署图。 |
| 12 | 展示两入口调用同一注册服务、纯计算与I/O分层。区分ES搜索、GraphQL精确读取和REST/Kafka发布；同URN锁仅进程内，发布后可查询确认可能超时。 |
| 13 | 身份、领域角色与操作权限贯穿前后端。本人完成相关扩展，DataHub 本身是上游平台。 |
| 14 | 元数据 Agent 将问题变为受权工具调用，返回实体和链接。它不是原开题的模型语义解释研究。 |
| 15 | 请求调度要一起考虑会话缓存、等待和观测滞后；算法由本人和同事共同设计，刷新与计量修复为本人直接实现。 |
| 16 | 按合成复现口径解释算法一的三个请求分支。10% 是候选比例，不是性能收益，也不是理论最优常数。 |
| 17 | 算法二只替换已有会话分支，把等待收益与缓存损失换成相同时间单位。该策略在本材料中属于理论与模拟，不宣称生产验证。 |
| 18 | 主动切换有收益也有退化。负值表示平均 TTFT 更低，正值表示更高；小缓存与旧快照可以改变方向。 |
| 19 | 调度依赖准确、及时的状态。介绍独立 Redis 刷新和 PipelineKey 重复计量修复，不展示内部原始配置或业务规模。 |
| 20 | 从自动发现部署ID讲到P侧running/waiting外连接聚合、精确连接、Redis与MGET。未匹配项显式诊断，API失效可选配置降级；状态年龄检测仍有待补强。 |
| 21 | 引入服务 simulator：直接挂载策略插件，以请求级服务后端和事件引擎完成实验。它没有逐 token 实现 P/D 连续批处理。 |
| 22 | 逐层说明TraceRecord、插件hook、Backend和归档接口。导入成功不等于插件真正参与决策，输入契约与探针检查同样必要。 |
| 23 | 工程优化侧重批量读写、变化集同步和适用场景下的内存替身。没有新增墙钟测速，不报加速倍数；TTL和Lua语义需要分模式说明。 |
| 24 | 开环固定输入到达过程，闭环固定并发并由完成触发补位。闭环完成率只对应指定模型和水位。 |
| 25 | 重点区分条件回放、经验估计和反事实预测。真实落点和耗时已经作为输入时，接近一致不构成独立预测验证。 |
| 26 | 四类合成校准自检按预期通过，但这仅验证分类方法。内存 Redis 替身对 TTL、Lua 和原子性的覆盖不完整。 |
| 27 | llm_repro 用明确 P/KV/D 和前缀缓存模型解释机制；服务 simulator 复用插件验证服务状态和路由。二者各有用途，不能互相冒充。 |
| 28 | Delm 适配把双 worker 协作落到共享看板，每个 worker 的 MCP 绑定自己的 actor。保留上游协作语义归属。 |
| 29 | 追加日志、claim、actor 和文件哈希解决不同问题。board.apply 的保护不覆盖直接编辑共享文件，不宣称全局事务隔离。 |
| 30 | 上游 Harness² 的并行组织是 k 基线、2k INV/DOM、k AGG；最终只从 AGG 选择，没有基线保底，不能说保证改进。本人负责运行时集成与可靠执行。 |
| 31 | 展示真实 Python→Node→TeamSession 调用链。rollout_ok 表示有可分析的运行证据，候选选择和任务验收还需要额外条件。 |
| 32 | 讲清Python与Node进程之间的版本化契约、输入参数、配置实际物化、stdout/stderr分流和结果目录。未知成本保留空值，不用0冒充已知。 |
| 33 | 重点讲本人具体工程：输入 staging、运行作用域、seed 内容比较、逐 worker 停滞。配置采纳与工作产物回收分别处理。 |
| 34 | 把配置diff/snapshot/adopt/rollback与workspace产物回收分开。配置回滚只恢复采纳涉及的文件；pull提取新增或已改任务文件，过滤项返回清单。 |
| 35 | 如实交代离线验证：Board 13/13、Node 三套 58/58。Python 全量有失败和错误；会话编排单测因 SDK 缺失未执行，真实模型端到端收益另需实验。 |
| 36 | 回到贡献归因：具体模块、直接实现、协作设计与团队/上游能力分别说明；不以提交或移入代码数量替代贡献。 |
| 37 | 原目标到成果的映射：专家部署形成可核验算法与工程链，预读取和激活语义未形成独立成果。Simulator 和 Agent 是后续扩展。 |
| 38 | 用可检验的研究问题结束正文：观测误差、仿真排序外推、Agent 固定预算盲评；此页可停留进入讨论，无致谢页。 |
| 39 | 副本阈值条件与复杂度补充。强调单副本瓶颈和设备组合目标不同。 |
| 40 | 历史统计用于决策、缓存实际命中在执行时计算。P95 的跨种子均值不是合并样本的 P95。 |
| 41 | M/G/1 解释利用率和服务波动；不严格等同 P/D 连续批处理，不把多个后端当单服务器。 |
| 42 | 给公开材料与仓库入口。Agent 的上游方法来源保留，原项目源码不随本演示稿分发。 |
