# 模型与实验口径

## 一、多个1P1D服务后端

N=4、8、16个独立后端；每个后端一个P实例、一个D实例和一条串行KV传输链路。一个“实例”是逻辑服务单元，不据此规定GPU数量。服务过程采用vLLM式P/D分离、前缀复用和迭代批处理的抽象；不仿真真实引擎内核。

请求在网关选择后端后，依次经过P等待、P执行、KV链路等待与传输、D准入等待及逐token解码。**本模拟定义首个D输出token对外返回为TTFT终点。**实际vLLM部署若由P先生成并立即返回首token，应改变统计边界，不能直接套用本模拟数值。

对请求r：

- P执行：0.008 + (n_r − L_ir)/3600 + 0.000003 n_r，单位秒。
- KV服务：0.003 + n_r/180000秒，传输完整输入状态。缓存命中减少P计算，但不在本模型中减少该请求P到D的传输长度。
- D每轮耗时：max(0.025,b/900) + 0.001 × 平均当前上下文长度/2048，b为本轮批大小；每轮为每条活跃请求生成一个token。
- TTFT = P等待 + P执行 + KV等待和传输 + D等待 + 首轮D执行。
- E2E = 到达至全部输出完成。D批容量16；新请求在迭代边界补入；P按FCFS逐请求处理，没有chunked prefill或P批处理。

速率、固定开销和容量是公开的建模参数，未用真实vLLM设备测量标定。KV显存只通过APC容量和D批容量近似，未模拟抢占、换出、碎片或OOM。无后端故障、跨集群缓存迁移、请求重试与取消。

### 输入与APC

每个种子生成固定1800条开环请求，160个会话，Zipf指数0.9；90%带会话亲和，输入由基础长度512/1024/2048/4096、增长历史和128个新token组成。普通输出从64/96/128/160等概率采样。会话请求可能重叠；后续prompt预先构造，不等待上条完成，也不把实际生成结果写回下一条prompt，因此这是前缀访问轨迹，不是完整多轮对话仿真。

缓存块32token，默认8192块，每个P独立LRU。亲和请求含8块公共前缀，其后是会话前缀和请求独有后缀。执行P时逐块查找最长连续前缀，首次未命中即停止；P完成后插入缓存。同一会话可能因为淘汰或转移而未命中，不同会话可能命中公共前缀。模型不把会话保持直接赋值为命中。

### 路由及观测

每0.25秒采样。后端APC比例是最近120个已完成P请求的命中token数/输入token数；模型组输入均值来自最近120N个已完成P请求。无统计时视为缺失，算法二保持原会话。

预计等待由P剩余服务、P等待队列估算、KV链路积压及D队列估算组成。D估计使用队列计数与配置的平均输出长度，不读取未来到达和请求真实剩余输出。低负载候选量使用P和D在途计数，加网关分配预留；该计数不含KV传输中的请求，KV压力单独进入预计等待。每次新快照发布时重置分配预留。状态延迟场景中，旧快照与预留的组合也是预测误差的一部分。

算法一的低负载量在这里是统一模拟协议中的P/D计数代理。生产实现的P侧计数口径见报告第7章；本模拟用于固定条件下比较会话保持和切换，没有逐行仿真生产网关。无亲和请求的A形态取最小负载，B形态做稳定散列。

算法二使用报告式（5.6）：
W_A − W_B > 1.2 × APC_A × 平均输入长度 / P有效速率。
B取最小预计等待候选。决策不读取B真实缓存，但执行时会计算B真实命中，因此模拟能暴露该简化的得失。不把稳健扩展式（5.9）的理论保证自动赋予本实现。

### 场景、重复及指标

10个场景，3个种子31/47/89，每次4种策略，共120次路由运行；具体参数在routing_configs.json。

- steady_4/8/16：总到达率7/14/28请求每秒。
- light_8：4请求每秒。
- hot_shift_8：14请求每秒，轨迹40%处会话热点平移。
- burst_8：上述热点变化，中间30%请求的到达率提高至2.8倍。
- decode_heavy_8：6请求每秒，输出长度4倍，观察长输出影响。
- small_cache_8：14请求每秒，APC缩到1024块。
- stale_8：14请求每秒，观测延迟2秒。
- no_apc_8：14请求每秒，禁用APC。

前20%到达请求用于缓存和状态预热，不计入路由统计，但完整参与执行。之后1440条全部完成后汇总。P95按nearest-rank，即排序后第ceil(0.95m)项。跨种子汇总是三个“各次均值/各次P95”的算术平均，P95均值不是混合样本的P95。相对变化=(算法二均值/算法一均值−1)×100%，正值为变慢。完整结果保留每个种子的原始值，不把三次重复解释为普遍收益的统计保证。

no_apc_8提供的输入工作量可能超过P服务能力；结果是**有限轨迹及排空**统计，不是稳态响应时间。completed_rps含最后排空时间，不能直接当成饱和吞吐。与生产中10%改善无换算关系。

## 二、EPLB复现

两个原函数位于vendor/omni_eplb_static.py，来源路径、快照和SHA见PROVENANCE.json。第一阶段按最大单副本压力分配额外副本；第二阶段受同卡唯一性和容量约束放置。贪心构造若失败，新增最大流仅返回合法布局，记录flow_fallbacks，不宣称负载最优。原函数体未修改。

对照：
- uniform：不读取热点，额外副本轮流分配，最大流构造一个确定性可行布局。此基线不优化放置负载。
- static：读取独立80窗口训练激活统计，执行一次原静态函数，之后保持。
- dynamic：从同一个static布局开始，用过去32步的激活均值，每16步评估一次。预测不均衡度>1.10、最大预测负载改善超过3%，且32步预测节省超过新增副本复制成本时更新。

每步1024次专家激活，多项分布采样；它们是逻辑专家激活次数，不是完整top-k门控token序列。各副本按轮转整数分担，激活数严格守恒。

每层计算时间(ms)=0.08 + 最大设备激活数/96。新增副本每份0.15ms；高复制成本场景1.5ms。迁移在更新步同步计入；不重叠的成本已经计算，不重复相加。初始权重加载不计入各策略测量窗口。这里的**单层服务时延**不是TTFT，也不是完整模型推理时间；没有细化all-to-all、权重尺寸、链路竞争和计算通信重叠。

默认E=32、设备8、每台槽位6；扩展到(E=16,设备4)及(E=64,设备16)，槽位仍为6。各对照资源预算一致。测试360步；稳态/突变/12步热点交替/均匀/两种规模/高复制成本共7场景，3种子，3策略，共63次。稳态和突变采用Zipf指数1.3；均匀场景的训练及测试均使用均匀概率。突变发生在测试中点，预测仅使用过去记录，不提前读取变化。

本动态策略是报告门槛思想的参考实现，不涵盖生产中的跨层预算、异步传输、映射版本控制或C++候选搜索。相对“uniform”的较大收益包含副本配置和放置两方面差异，不能归为某一单独机制。
