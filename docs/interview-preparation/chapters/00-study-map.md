# 00 阅读方法与项目地图

这份手册用于陶壮的项目面试准备，配套《大模型基础设施与 Agent 工程》Beamer。目标是能独立解释项目背景、画出执行链路、说明自己的设计和实现，并在继续追问时区分代码事实、理论结论和待验证部分。它包含本机源码阅读路径与诊断记录，作为个人学习资料保存。

## 1 先建立完整项目地图

| 大项目或方向 | 本文讨论的具体工作 | 先学清楚的关系 |
|---|---|---|
| OmniInfer 推理框架 | OmniPlacement 专家均衡及模型和框架适配 | OmniAttn、OmniProxy 与专家均衡是团队框架中的不同能力 |
| Omni-EPLB 独立 SDK | Python与C++接入、统计、候选、权重及映射更新 | 它延续相关能力，不代表替代全部 OmniInfer，也不是另造一套同名原创算法 |
| 企业数据工程平台 | DataHub扩展、注册SDK、身份权限、页面与Data Agent | DataHub是上游元数据底座；产线、任务与Runtime是团队平台背景 |
| Omni-ELB 的 LiteLLM 路径 | 协作路由、独立状态刷新和指标修复 | 应用入口、网关选集群、后端内部P/D执行各有职责 |
| 路由 simulator | 真实插件、请求事件、服务耗时后端与实验 | 它在生产链路外；与本仓库llm_repro模型不同 |
| 编码 Agent 平台 | Delm双worker适配与Harness²执行接入 | 团队平台、上游方法和个人工程改造分别归因 |

每个项目都先准备三句话：谁在用，遇到什么问题，我具体负责哪一段。例如“用户通过网关访问多个模型后端，热点会话会造成缓存和负载之间的矛盾；我与同事设计路由，并实现状态刷新和计量修复”。先让面试官听懂对象，再展开工具名。

## 2 阅读时识别四种证据状态

【已实现】指所读源码存在相应实现或可追溯历史贡献，不自动代表本机已经跑过全部测试、所有失败场景均有保证，也不代表代码全部由个人独立完成。

【理论/复现】指数学模型、性质分析或合成输入下的模拟。必须说明假设、目标、计量单位和实验范围。理论式成立不代表实际部署已经逐项实现该式。

【通用知识】是理解项目所需的计算机原理。例如进程内锁不能协调两个服务副本、调用async函数会返回可等待对象、服务时间方差影响排队。这些知识可以用于解释设计，不应当作自己的专有发明。

【改进建议】是可以继续做的方案。回答时使用“如果继续改，我会……”并给出验证方法，不能把它说成当前已经上线。源码核查中发现的风险会明确写成“当前快照的风险和测试缺口”，不靠旧注释掩盖。

## 3 分三轮学

第一轮读每章开头、执行主线和个人职责，不看代码先画图。能用两分钟讲清项目背景、个人模块、输入输出和主要取舍，再进入下一轮。建议先学推理，再学网关，按岗位重点提前读Agent。

第二轮沿一个token、注册请求、网关请求、完成事件或看板任务追代码，标注“谁调用、读写什么、失败如何返回”。遇到异步、进程、语言、设备或存储边界，追问所有权和完成条件。

第三轮闭卷答题，每题先用60秒回答再对照答案。除正常路径，还要能解释状态过期、取消、并发、重试、版本和测试缺口。每章至少做一个练习，并解释答案为何成立。

面试时先说结论，再给例子，最后说明边界。参考回答提供论证骨架，不必逐字背诵。

## 4 每个项目都应能回答的八件事

1. 项目目标用户、输入和最终输出分别是什么。
2. 哪些是团队或上游能力，哪些是我直接实现或共同设计的。
3. 一次操作怎样穿过模块，状态在哪些边界发生变化。
4. 核心算法的目标和约束是什么，工程实现用了哪些近似。
5. 为什么选择当前方案，与一个现实替代方案有什么取舍。
6. 哪个不变量最重要，代码如何维护，什么故障会破坏它。
7. 哪些验证已完成，哪些只是设计建议，指标到底怎样算。
8. 如果重做一次，我会先改哪件事，用什么证据判断改对了。

## 5 技术栈应该与具体问题绑定

不要只背“我会C++、Python、Java、Redis、Node”。用项目解释：C++/Python绑定服务于设备权重和高频统计；FastAPI/Pydantic组织元数据服务边界；Java/GMS/Play解决身份和凭证衔接；Redis/Prometheus连接路由决策与观测；Node/EventEmitter/MCP组织协作执行；文件哈希帮助判断输入、改动与覆盖冲突。

区分两个容易说错的名字。DataHub中的MCP通常指MetadataChangeProposal，即元数据变更提案；Agent工具中的MCP指Model Context Protocol。说“我用了MCP”必须先讲在哪个项目、是哪一种。数据平台的个人前端实践包括React/TypeScript；编码Agent平台的团队前端底座是原生JavaScript/CodeMirror，不能串成同一份个人前端经历。

## 6 如何使用本地证据

入口先看[面试Beamer](D:/博士后出站考核/llm-scheduling-repro/docs/beamer/project-introduction.pdf)和[讲述提示](D:/博士后出站考核/llm-scheduling-repro/docs/beamer/speaker-notes.md)。需要全景时看[工程技术报告](D:/博士后出站考核/llm-scheduling-repro/docs/技术报告.md)，需要当前调用链细节时，以本手册各章标明的源快照和函数为准。旧README、注释、历史总结可能与当前函数体不同。

使用只读 `git show`、小例子和既有测试理解边界，无须切换证据分支或调用真实模型。本地链接依赖当前工作区，源项目不随手册打包；练习不用真实业务轨迹或凭证。

个人提交支撑具体实现，论文消融支撑团队系统条件下的组件结果，合成模拟支撑模型内现象；三种证据不能互换。内部验收与公开模拟也须分别表述。
